# 介绍

## 海信 · 数字化门店 PC 端设计系统

让 AI 按规范生成可交付的 BI 后台页面。

基于 **Arco Design 组件 + 覆盖 token**（`references/digital-store-tokens.css`），以 **8px 栅格节奏**约束生成，让需求落进代码、让结果直接进入交付。

| 指标 | 数值 |
|---|---|
| 规范章节 | 74 |
| 组件条目 | 64 |
| 图标 | 492 枚 / 9 分类 / 10 档尺寸（实体在 `references/icons/`） |
| 页面模板 | 5（1 通用框架 + 4 典型页面） |
| 自检清单 | 24 条 + 第 13 节 20 条硬规则 |

### // 01 为什么需要

#### 别再让 AI「凭感觉」写 BI 后台

直接让大模型生成报表页面，往往踩中三类问题——数字化门店规范用设计系统逐一约束。

| 问题 | 解决方案 |
|---|---|
| 每次生成的色彩、字号、间距各不相同，不符合企业规范 | tokens 唯一事实源：品牌绿 `#00AAA6` 分档使用，字号 / 间距全部落档位 |
| 组件随手拼、自造组件，交接后难以维护 | 只用 Arco 组件 + 覆盖 token，参考 64 个组件条目，不自造 |
| 产出停在「看着像」的截图，无法直接进开发 | 自开发 / QBI 双模式规格 + 24 条自检 + 20 条硬规则，直接可交付 |

### // 02 能做什么

#### 从规范到真实页面

覆盖生成、约束与交付的关键环节。

**01 页面模板套用**
典型页面都套同一固定框架（渐变底 + 178 左导航 + 页签 + 报表容器），宽度随视口流式、窄屏侧栏转抽屉，按场景选 1 个通用框架 + 4 个典型页面，不从零设计。

**02 组件规格**
按钮、指标卡、趋势图、Tabs、筛选器、表格、导航、图表等 64 个条目，尺寸、状态、取值全部落 token，选型有据可依。

**03 双开发模式**
自开发（指标卡 232/237 宽、按钮描边款、筛选器 `0 8px 0 0`）与 QBI（指标卡 252 宽、品牌实心按钮、筛选器白卡 88）两套规格正交选用，不混搭。

**04 8px 栅格节奏**
数字化门店 8px、服务指南针及通用 BI 12px；间距、卡片净距、栅格槽按节奏取值，不另估。

**05 图标体系**
10 档尺寸全部 1:1，默认填充 `#4E5969`、需要品牌绿时用 `primary-7`；inline SVG + `fill: currentColor`，不用 iconfont / emoji。

**06 自检与门禁**
交付前过 24 条自检清单与第 13 节 20 条硬规则（红好蓝差、品牌色分档、圆角只有 4/8、Tab 层级、控件高度、窗口自适应与内容区滚动、组件强制走组件库等）。页面只允许「模板骨架 + 组件库 + 页面布局 CSS」三层：按钮走 `.btn` 模板、控件只用组件库、页面 `<style>` 不重定义组件类（详见 `SKILL.md`「组件强制约束」）。生成全程按五步强制流程执行（业务场景分析 → 组件库匹配 → 组合方案 → 生成 → 合规校验报告），顺序不可调换，Step 5 报告随交付输出。

### // 03 怎么工作

#### 从一句话到可交付页面

「先判定场景与开发模式、再按规范生成」是贯穿始终的主线。

1. **描述需求** — 用自然语言说明页面 / 业务，或直接给 PRD。
2. **需求规格化** — 转成界面架构描述（页面、区块、数据、交互），少量澄清后确认。
3. **判定两根轴** — 场景轴（数字化门店 8px / 服务指南针 12px / 通用 demo）；模式轴（QBI / 自开发，默认自开发）。
4. **规范生成** — 按 Skill 内置的五步强制流程执行（业务场景分析 → 组件库匹配 → 组件组合方案 → 生成 Demo → 合规校验报告，顺序不可调换、校验报告必须随交付输出），复制 `references/template/app-shell.html` 整页，改 `MENU` / 页面数据与渲染函数，缺区块时从 `blocks.md` 取；取值来自 tokens，组件不再重写。
5. **自检交付** — 24 条清单 + 20 条硬规则逐项过，交付说明标注模式与假设。

页面里的每个区块都直接取规范章节的组件——指标卡 `.ind`、侧边导航 `.sn`、页签 `.page-tabs`、筛选器 `.filterbar` + DateSelected `.u-dsel` + 按钮 `.btn`、趋势图 `.chart`、AI 辅助分析 `.u-ai`、表格 `.data-table` 与标签 `.tag`；**不允许自造简化版**（灰块顶指标卡、两条线顶图表、纯文字顶 AI 区块），否则 demo 和组件规范会裂成两套外观。

#### 模板包：新页面从这三份文件开始

`references/template/` 是组件的唯一实现。生成新页面的第一步是复制它，而不是照 md 重写：

| 文件 | 内容 | 改哪里 |
|---|---|---|
| `app-shell.html` | **可运行的多页模板**：首页入口 + 核心指标达成 + 财务开单；侧导航、页签、筛选器、日期面板、趋势图、表格、AI 辅助分析全部实现，组件样式内联，只依赖 `../digital-store-tokens.css` | `MENU`、`state`、`homeHtml()` / `pageHtml()` / `fbHtml()`、`TAB_META`，以及脚本顶部的 `METRICS` / `AI_ROWS` / `FB_T_*` / `FB_PRICE` 等数据常量 |
| `components.css` | `.ind` / `.btn` / `.data-table` / `.u-ai` / `.chart` 等全部组件外观（从模板页抽出） | 已有工程增量接入时引用；缺能力先在这里补，再同步规范页 |
| `blocks.md` | 指标卡 / 图表 / 表格 / AI 的可复制片段，自开发与 QBI 两套 | 往已有页面加区块时直接粘 |

- **场景**：`<html data-scene="store">` 走 8px，其他值（`"compass"` 及非这两个系统的标识）走 12px。节奏统一收敛到 `--page-gap`（8 / 12），内容区外边距、卡片间距、面板内距都取它；场景只写在 html 属性这一处。
- **模式**：`<html data-mode="self">` / `"qbi"`，自动切筛选器容器与按钮形态；指标卡变体仍按内容显式选，QBI 卡加 `ind-qbi`。同样只改 html 属性。
- **系统名称**：`data-scene="store"` 显示「数字化门店」，`"compass"` 显示「服务指南针」；其他系统写 `<html data-brand="系统名称">`。未写时页面显示「未命名系统」并在控制台提示——此时先问用户系统名称，不要拿「数字化门店」占位。名称过长时侧栏自动省略号，`title` 保留全称。
- **导航与页签**：`MENU` 是当前系统的实际菜单（最多两级，一级项用 `page` 指向入口页、二级项用 `tab` 指向报表页）；`state.tabs` 是当前打开着的页面，首页固定最左，报表页签可收藏 / 关闭，切走再切回恢复该页筛选与视图（`snapshotTab` / `restoreTab`）。换系统整段替换 `MENU` 与页面函数，不要保留模板里的营销菜单。
- **页面结构**：`.tpl-page > .sn + .tpl-main`，`.tabs-row`（抽屉开关 + `.page-tabs`），`.tpl-report > .filterbar + .tpl-scroll > .tpl-title + .tpl-body`；首页是入口页（`.home-cards` 卡片进入两张报表）。没有顶栏，内容区直接在 `100dvh` 内滚动。
- **取值**：直接 `<link>` tokens；单文件交付时把 tokens 内联后删掉 link。不要整份改成本地色值。
- **联动**：筛选变化派发 `ds:filterchange`，按钮派发 `ds:action`；页头能力在 `window.DSShell = { scene, mode, brand, toast }`，提示统一用 `DSShell.toast()`。
- **导航结构**：侧栏最多两级；三级信息改用页面内二级页签，不往侧栏里塞。

#### 窗口自适应是默认要求

生成的页面以浏览器窗口为画布，设计稿尺寸（1440×900、1254 / 1238 等）只作参考基线：

- **宽度流式**：指标卡 `repeat(auto-fill,minmax(230px,1fr))` 自动换列；筛选器可换行、select 可收缩；断点 1240 / 1024 / 760 / 560 分别处理筛选器换行、侧栏转抽屉、筛选器 2×2 与表格横向滚动、控件纵向堆叠。
- **高度不裁切**：桌面框架 `height:100dvh`（模板无独立顶栏，页签行在内容区内），内容区 `flex:1;min-height:0;overflow:auto`，**内容超出时自动出现纵向滚动条**，能滚到最后一个区块；≤1024 回到文档流自然滚动。
- **图表跟随容器**：按 `clientWidth/clientHeight` 实测绘制，窗口 resize 防抖重绘，不用固定 viewBox 拉伸。

细节与自检清单见 `digital-store-spec.md` 第 10.5 节。

### // 06 有何不同

#### 和直接让 AI 写前端的区别

同样是 AI 生成，约束与交付质量是两回事。

| 维度 | 普通 AI 生成 | 数字化门店规范 |
|---|---|---|
| 视觉一致性 | 每次风格不同、容易跑偏 | tokens 唯一事实源，品牌绿分档、字号间距落档位 |
| 规范符合度 | 取决于模型发挥 | 强制 Arco + 覆盖 token，24 条自检把关 |
| 组件选型 | 随机使用甚至自造组件 | 64 个组件条目 + 双开发模式规格，有据可依 |
| 可交付性 | demo 感重、难以落地 | 自开发 / QBI 双模式 + 20 条硬规则，可直接进开发 |
| 可维护性 | 一次性代码、结构随意 | 固定页面框架 + 组件章索引，回归有据 |
| 窗口自适应 / 多端 | 常被忽略 | 窗口自适应是硬约束：流式布局 + 1240/1024/760/560 断点，内容溢出自动滚动，不受设计稿固定尺寸限制 |

### // 07 核心机制

#### 设计理念

**01 需求先规格化**
任意颗粒度输入先转成界面架构描述、少量澄清并经你确认后再生成；命中页面模板的页面以该模板结构为基准。

**02 Skill 是唯一事实源**
规则、token、组件规格、页面模板都收敛在 skill 内；规范展示页只是快照。

**03 双轴判定**
场景轴决定栅格节奏与执行依据，模式轴决定组件尺寸与按钮样式，先判后写。

**04 结构不变量**
章节编号连续、目录同序、图标走 sprite、CSS 类定义即使用、颜色走 token——规范页每次新增章节都必须保持。

**05 门禁保交付**
生成后按 24 条自检 + 20 条硬规则逐项核对，交付说明如实标注模式、假设与未实测项。

**06 规范页即样例**
`digital-store-spec.html` 本身就是照着本 skill 建的单文件规范页（dogfood）。

# 使用指南

你只管把 **需求** 说清楚——读规范、取 token、生成页面、自检都由 skill 处理。说得越明确，澄清越少、生成越准。

### 这些 skill 自动处理，你不用操心

#### 读规范与取 token

自动读取 `references/digital-store-spec.md` 与 `digital-store-tokens.css`，颜色、字号、间距、圆角、阴影、层级全部从 token 取值，不让你手填色值。

#### 判定场景与模式

自动判断 8px / 12px 节奏、自开发 / QBI 模式，不用你指定；判断有分歧时会在交付说明里写明假设。

#### 自检交付

生成后按 24 条自检清单与 20 条硬规则逐项核对；规范页新增章节时还会跑结构不变量校验（章节编号、图标引用、CSS 类、标签配平）。

### 你真正要关注的

#### 把需求说清楚

skill 写页面前会先给你一份界面结构说明并请你确认。把下面这些点说清楚，就能少几轮澄清、更快拿到贴合预期的结果：

- 场景：数字化门店 / 服务指南针 / 通用 demo
- 开发模式：自开发 / QBI（不确定就留给 skill 判，默认自开发）
- 页面形态：列表 / 指标卡仪表盘 / 趋势分析 / 详情 / 表单
- 每页分几块：大标题、筛选器、指标卡行、图表、表格、AI 辅助分析
- 筛选器要哪些控件：日/周/月/年胶囊、日期范围、select、重置
- 数据来源：mock 还是真实接口
- 特殊交互：页签切换、Tab 层级、长页面冻结列、AI 辅助分析

#### 同一个需求，两种说法

**偏模糊（要多轮澄清）**
> 「做个销售报表页。」

**更明确（一步到位）**
> 「做个数字化门店自开发模式的销售总览：大标题带日期说明、筛选器（日/周/月/年胶囊 + 日期范围 + 渠道/品类 select + 重置）、5 个指标卡、趋势图（实际 + 同比虚线）、底部 AI 辅助分析；数据先用 mock。」

#### 澄清与确认流程

1. **你** 给一句话或一段需求，例如「做一个门店生命周期页面」。
2. **skill 追问** 把关键模糊点一次性打包问（哪个场景？自开发还是 QBI？页面要哪些区块？数据 mock 还是接口？），最多 1–2 轮。
3. **skill 产出** 一份界面结构说明：页面框架、区块顺序、关键组件 / 取值 / 交互。
4. **你确认** 确认或直接改结构（区块增删、模式切换）。
5. **skill 生成** 按确认的结构生成，并过自检。

确认后才进入生成——避免边写边猜、来回返工。

#### 说清「形态」，更容易命中模板

点明「页面形态 + 区块规模 + 是否自开发/QBI」，skill 会按下面的关系选型：

- 要搭一个新典型页 → 通用页面框架（5313:9671）
- 销售/核心指标看板，自开发 → 核心指标达成（5313:9322）
- 服务备件类 QBI 报表 → 服务备件管理（5313:8385）
- 行业份额、带一级 tab 与悬浮球的分析页，自开发 → 市场份额（5313:9723）
- 门店全生命周期长页面（冻结列）→ 门店生命周期（5313:10682）

匹配度低时按规范自主拼装，但仍只用 Arco 组件 + token。

#### 给产品经理

不熟悉代码也没关系：你只需在对话里描述需求、在浏览器里看效果。规范页第 72 节的页面模板区里，缩略图就是页面的等比缩小版（同一份 DOM），点缩略图进入完整页面、左下角「返回」回目录；交付说明会如实标注哪些做了静态校验、哪些未做浏览器实测。

# 通用版

**数字化门店通用版**：不限 Arco 技术栈，也不规定页面模板，只约束 **视觉语言、品牌与栅格**。所有取值来自 `references/digital-store-tokens.css`，与 Arco 版同源。

### 包含什么

#### 取值

`digital-store-tokens.css`：灰度 / 主色 / 状态色 / 图表色 12 + 业务语义色 8、字号、间距、圆角（只有 4 与 8）、阴影、层级、组件级尺寸。

#### 设计规则

颜色分档、排版、间距、圆角、控件密度、布局等规则（见 `digital-store-spec.md` 第 1–6 节与第 13 节 20 条硬规则）。

#### 组件规格

按钮、指标卡、趋势图、Tabs、筛选器栏、表格与标签、SideNav 等的尺寸与状态矩阵，值都落到变量（第 7–12 节）。

#### 交互要求

筛选器联动、下拉面板、空 / 加载 / 错误状态、焦点与键盘、点击区域、文案（`web-baseline.md` 交付底线 + 第 13 节）。

#### 品牌与图标

品牌绿分档（`primary-6` 大色块、`primary-7` 图标边框、`primary-8` 链接文字、`brand-light` 轻背景）；功能性图标统一 inline SVG + `currentColor`，尺寸 10–48 十档。

#### 改造已有界面

把已有原型或工程改到数字化门店规范：先建结构基线（功能、文案、区块顺序默认不改）→ 盘点原取值 → 输出映射表（颜色按角色、尺寸就近取档）确认 → 分批替换，每批核对保真。

### 选哪个版本

| 你的情况 | 使用 |
|---|---|
| 技术栈是 Arco，想直接用 8px 节奏、页面模板与双模式规格 | 本 skill 的 Arco 版（`digital-store-spec.md`） |
| 原生 HTML、Vue + Element Plus、React + Ant Design、Tailwind 等其它技术栈 | 通用版（本节 + `digital-store-tokens.css`） |

### 接入各技术栈

先引入 `digital-store-tokens.css`（不要放进 CSS `@layer`），再把组件库的主题变量指向 token；暗色（若需要）统一在根元素加 `data-theme="dark"`。

| 技术栈 | 引入方式 |
|---|---|
| 原生 HTML / 无组件库 | 直接 link `digital-store-tokens.css`，间距圆角只用变量 |
| Vue + Element Plus | tokens + 覆盖 `--el-color-primary` 等到 `--primary-primary-6`，圆角 4/8 |
| React + Ant Design | tokens + ConfigProvider theme（主色 `#00AAA6`、圆角 4/8、字体栈） |
| Tailwind | tokens + `@theme` / config 映射（主色、灰阶、间距、圆角 4/8） |

适配只解决取值，组件规格与交互要求仍需遵守；两套筛选器外观（自开发 / QBI）不要混用。

### 交付前自检

- 颜色、字号、间距、圆角只用 token 变量或档位，不写字面色值
- 圆角只有 4 和 8（例外：指标卡内层 6、小标题图标 6）
- 涨跌「红好蓝差」，状态不只靠颜色，正文对比度 ≥ 4.5:1
- 同一筛选行的控件高度统一（select / 自开发胶囊 32，datepicker / QBI 胶囊 34）
- 空、加载、错误状态都有呈现
- 窗口自适应：1440 / 1024 / 760 / 390 各档无横向滚动与重叠，窗口变矮时内容区自动出滚动条、无内容被裁切
- 改造已有界面时：功能、文案、数据、区块顺序与改造前一致
