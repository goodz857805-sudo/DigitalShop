本文是**执行依据**。生成或优化数字化门店 / 服务指南针页面时，按本文取值，不凭审美即兴发挥。
取值来源：Figma `[B]数字化门店_3组件库PC端`（fileKey `XGIf7PEfWNEA7WTxxDwJ8b`），
变量已整理为 `references/digital-store-tokens.css`，直接粘用，不要另行估值。

## 证据等级

原始文档把每条规则分成三档，本文原样保留。**「待确认」的条目不要当硬约束执行，也不要在交付说明里宣称它是标准。**

| 标记 | 含义 | 生成时怎么处理 |
|---|---|---|
| 【确认】 | 文档明确写定，或用户已确认 | 强制执行 |

## 1. 两根轴：先定场景，再定开发模式

取规范前先回答两个问题。两根轴**正交**：场景只决定栅格节奏，开发模式只决定组件形态，互不推导。

### 1.1 场景轴 → 决定边距与栅格槽

服务指南针与数字化门店**共用同一套组件库**，唯一差别是边距与栅格槽：

| 需求关键词 | 边距 | 栅格槽 | 取用变量 |
|---|---|---|---|
| 含「数字化门店」 | 8px | 8px | `--grid-margin` / `--grid-gutter` |
| 含「服务指南针」 | 12px | 12px | `--grid-margin-report` / `--grid-gutter-report` |
| 两者都没有 | 12px | 12px | 同上（默认） |

**8px 是例外，12px 是默认。** 拿不准就用 12px——宁可保守，不要把报表类页面套成 8px 节奏。

### 1.2 开发模式轴 → 决定组件形态

报表有两种开发模式，同一类组件在两边的规格不同，**不要混用**：

| 开发模式 | 关键词 | 组件来源 | 典型特征 |
|---|---|---|---|
| 自开发 | 自开发、自研、定制页面 | 组件库「自开发」系列 + 通用系列 | 指标卡窄（232/237）、按钮描边款 |
| QBI | QBI、QuickBI、仪表板嵌入 | 组件库「QBI」系列 + 通用系列 | 指标卡统一 252 宽、按钮品牌实心 |

判定规则：

1. 需求里出现「QBI」→ 走 QBI 规格。
2. 需求里出现「自开发」→ 走自开发规格。
3. **都没说** → 默认自开发，并在交付说明里写一句「按自开发组件规格生成，如果实际走 QBI 请告知，指标卡与按钮形态会变」。
4. 通用组件（按钮五型四态、Tab 三级、页签、表格、弹窗等）两边共用，不受开发模式影响。

## 2. 技术栈【确认】

生成代码时**直接引 Arco 组件 + 覆盖 token**，不手写组件、不换成别的组件库。

- 颜色、字体、圆角、阴影、层级：只用 `digital-store-tokens.css` 里的变量，不写裸值。
- 组件：用 `@arco-design/web-react`（或工程实际使用的 Arco 包）的现成组件，通过 CSS 变量 / 主题配置覆盖。
- 底层色板本身就是 Arco 的 gray / red / green / orange / blue 色阶，覆盖成本很低——**不要另建一套调色板**。

覆盖入口（按工程实际情况选一个，不要混用）：

```css
/* 方式一：直接覆盖 CSS 变量 */
:root {
  --primary-6: var(--primary-primary-6);
  --danger-6: var(--danger-danger-6);
  --color-text-1: var(--text-color-text-1);
}
```

```ts
// 方式二：走 Arco 主题配置（React）
import { ConfigProvider } from '@arco-design/web-react';
<ConfigProvider theme={{ primaryColor: '#00aaa6' }} />
```

## 3. 五条会翻车的硬规则

这五条与通用设计直觉相反，必须逐条遵守。生成后优先检查这五项。

### 3.1 红好蓝差【确认】

> 「本业务采用红好蓝差：表现好用红，表现差用蓝。危险红表达风险或错误，与业务趋势不是同一个语义。」

```css
--semantic-semantic-performwell: #f53f3f; /* 表现好 · 红 */
--semantic-semantic-performbad:  #3491fa; /* 表现差 · 蓝 */
```

- 上涨、达成、超额 → **红**；下跌、未达成 → **蓝**。
- 这套只用于**趋势与业绩**。错误提示、危险操作仍用 `--danger-danger-6`，两者都是红，**必须靠文案或图标区分**，不能只靠颜色。
- `--status-*` 不能按字面理解：`--status-danger` 指向 performwell，实际含义是「业绩上扬」。不确定就别用 series，直接取 `--businesssemantic-bs-*`。

### 3.2 品牌色分三档用【确认】

`#00AAA6` 白底对比度只有 **2.88:1**，直接拿它写文字或图标会既不好读也不合规。

| 用途 | 变量 | 色值 | 白底对比度 |
|---|---|---|---|
| 大色块、面积填充、选中底 | `--primary-primary-6` | `#00AAA6` | 2.88:1 |
| 图标、边框、选中指示 | `--primary-primary-7` | `#009093` | 3.88:1 |
| 链接文字、白字主按钮 | `--primary-primary-8` | `#00757B` | 5.48:1 |
| 轻量强调背景 | `--primary-brand-light` | `#F2FBFB` | — |

规则：海信绿只用于**主要操作、重点状态和链接**；品牌浅色只做轻量强调背景，**不替代通用页面底色**。不要用 Tailwind 的 teal 色板替代这四个值。

### 3.3 圆角只有两档【确认】

桌面一级模块 8px；二级模块、按钮、标签 4px；移动端 4px。

> 「除原规范已明确的 4 / 8 外，其余只描述现有实例；**不新增整套 12 / 16 / 24 圆角体系。**」

**Arco 默认圆角里有 16px，照抄就违规。** 组件内部按各自层级取值，不要把嵌套层全压成同一个值。页面上能看到 0/2/4/6/8/20 这些值，都是历史实例，不要新增使用。

### 3.4 字体必须带 fallback 栈【确认】

```css
--font-family-cn-stack: "PingFang SC", "Microsoft YaHei", "Source Han Sans SC", "Noto Sans SC", sans-serif;
--font-family-num-stack: "D-DIN-PRO", "Barlow Semi Condensed", ui-monospace, monospace;
```

**PingFang SC 只在 macOS/iOS 存在**，这是 Windows 为主的 PC 后台，只写单个字族会静默掉到默认字体，规范等于没生效。
**D-DIN-PRO 不是系统字体**，必须自托管 woff2，否则指标卡数字会 fallback，视觉直接垮掉。落地前确认工程里有字体文件。

### 3.5 三级文字不能当 14px 正文【确认】

| 变量 | 色值 | 白底对比度 | 允许的用途 |
|---|---|---|---|
| `--text-color-text-1` | `#1d2129` | 16.1:1 | 正文主色 |
| `--text-color-text-2` | `#4e5969` | 7.1:1 | 次要文字 |
| `--text-color-text-3` | `#86909c` | **3.24:1** | 仅 ≥18px，或单位、注释等辅助信息 |
| `--text-color-text-4` | `#c9cdd4` | **1.6:1** | 仅占位符、禁用态 |

`text-3` 挂 14px 正文低于 WCAG 4.5:1。指标卡里的「环比 / 同比 / 完成率」这类标签可以用它，但那是因为它们不是阅读内容。

## 4. 字体规范【确认】

### 4.1 中文层级（PingFang SC，字距 0）

| 字号/行高 | 字重 | 用途 |
|---|---|---|
| 12/16 | 400 | 辅助信息、桌面端最小字号 |
| 12/16 | 600 | 辅助强调、表头 |
| 14/22 | 400 | **正文基准** |
| 14/22 | 600 | 模块标题、Tab |
| 16/24 | 600 | 页面标题 |
| 18/28 | 400 | 扩展常规 |
| 18/28 | 600 | 扩展强调 |

### 4.2 数字层级（D-DIN-PRO SemiBold 600，字距 0）

| 字号/行高 | 用途 |
|---|---|
| 14/18 | 辅助数值 |
| 24/28 | 小指标、主数据 |
| 36/36 | 大指标、强调数据 |

数字要开等宽：`font-variant-numeric: tabular-nums`。单位（亿/万/%）字号退一档、颜色用 `--text-color-text-3`，**不要整体加粗**。

### 4.3 最小字号

桌面 12px，移动 10px。低于这个值不要用。

### 4.4 行高以「实际」为准

文档里有一份「实际 vs 建议」差异表，**建议值尚未应用**，不要采用：

| 对象 | 实际（采用） | 文档建议（不采用） |
|---|---|---|
| 中文辅助 12px | 12/16 | 12/18 |
| 中文正文 14px | 14/22 | 14/22（一致） |
| 中文标题 16px | 16/24 | 16/24（一致） |
| 数值 24px | 24/28 | 24/32 |
| 数值 36px | 36/36 | 36/44 |

三个「数值/No-Bold」样式同名，**必须按字号区分**，不要因为名字带 No-Bold 就当成常规字重——它实际是 SemiBold 600。

## 5. 间距与栅格【确认】

桌面 24 列 Stretch 栅格：主工作区左右 Margin、Gutter、行间距均为场景值（8 或 12）。
主工作区**不含 178px 侧栏**；列宽随可用宽度伸缩，小数不逐列取整。

1440 宽页面（数字化门店）推算：

```
主工作区 W = 1440 − 178 = 1262px
全宽内容   = 1262 − 8 × 2 = 1246px
跨列模块间保持 8px 净距，按实际 W 计算
```

旧样板的 1254px 是观察到的容器值，**不与新计算混用**。

### 5.1 已确认的间距刻度

| 值 | 状态 | 用途 |
|---|---|---|
| 8px | 【确认】 | 页面主规则：边距、栅格槽、行距、卡片内距、卡间距 |
| 16px | 【实例】 | 组件内部用法，如筛选器左右内距 |
| 4 / 24 / 32 | 【待确认】 | 扩展刻度建议，需结合组件语义，不是已有变量 |

> 8px 是**页面容器规则**，不要求把所有组件内部 spacing、文字行高、控件内距都改成 8。

### 5.2 页面骨架实测值

| 项 | 值 |
|---|---|
| 侧栏宽 | 178px |
| 顶区高 | 42px |
| 筛选行高 | 48px |
| 标题区高 | 48px |

## 6. 阴影【确认 + 待确认】

**常规白卡优先靠「背景 + 边线」区分，不是加阴影。** 阴影表达表面深度，不代表 CSS 层级；无阴影不等于无边界。

| 用途 | 值 | 状态 |
|---|---|---|
| 页面容器 | `1px 1px 8px 0 rgba(0,0,0,0.08)` | 【实例】观察 12 处 |
| AI 页面容器 | `0px 2px 6px 0 rgba(139,144,162,0.1)` | 【实例】观察 4 处 |
| elevation-0 | 无阴影 | 【待确认】常规白卡 |
| elevation-1 | `1px 1px 8px 0 rgba(0,0,0,0.08)` | 【实例】有依据 |
| elevation-2 | `0 4px 16px 0 rgba(0,0,0,0.12)` | 【待确认】 |
| elevation-3 | `0 8px 24px 0 rgba(0,0,0,0.16)` | 【待确认】 |

注意：阴影方向与透明度**按原实例保留**，不要统一成通用悬浮层。品牌绿阴影只用于已观察的品牌装饰；移动 Tabbar 用横向偏移。

检查项：阴影不被父容器裁切；不堆叠重复阴影；浅色背景下仍能辨边界；阴影与 Z-index 分开管理。

## 7. 层级 Z-index【待确认】

以下 9 档是文档的补充建议，**尚待研发确认**，交付时标注为建议值。

| 名称 | 值 | 用途 |
|---|---|---|
| base | 0 | 常规内容：页面、图表、表格 |
| sticky | 100 | 吸顶区域：顶栏、固定表头 |
| dropdown | 200 | 页面下拉：筛选下拉 |
| floating | 300 | 悬浮操作：助手、浮动按钮 |
| backdrop | 1000 | 模态遮罩，阻断背景交互 |
| modal | 1010 | 弹窗 / 抽屉内容容器 |
| modal-popover | 1020 | 弹窗内下拉，属于当前弹窗上下文 |
| toast | 1100 | 全局轻提示 |
| tooltip | 1200 | 当前上下文提示 |

两条实施边界：

- **只在同一 Stacking Context 内可比。** 子元素 z-index 再大也不能跨越父级上下文——先定父级，再比内部子层。
- **重叠可见性**：页面普通态可同时出现吸顶、页面下拉、悬浮助手；进入模态后关闭背景浮层，只保留当前弹窗内部的下拉与提示；全局轻提示位于模态之上。

## 8. 颜色使用分工

颜色分八层，**按层取用，不要跨层**。

| 层 | 变量前缀 | 用途 |
|---|---|---|
| 基础 | `--color-*` | 纯黑白 |
| 灰度 | `--gray-gray-1..10` | 中性层次 |
| 品牌 | `--primary-primary-1..10` | 主操作、重点状态、链接 |
| 界面语义 | `--line-color-*` `--fill-color-*` `--text-color-*` | 描边、填充、文字 |
| 状态语义 | `--success/danger/warning/info-*` | 成功、错误、警告、提示 |
| 海信品牌层 | `--higreen-*` | 表格头、页头、Tab 底、指标卡底 |
| 组件用色 | `--card-*` `--table-*` `--indicatorcard-*` | 具体组件 |
| 图表 | `--chart-chart-1..12` | 数据序列 |
| 业务语义 | `--businesssemantic-bs-*` | 目标、实际、同比、环比、完成率、YTD、基准线 |

### 8.1 表格用色

表头、分区、强调、合计各有专用色，**表格边框与旧文档分割线不是同一色值**，按来源分别引用。

```css
--table-table-head:      var(--higreen-higreen-table);      /* #e0f1f5 */
--table-table-border:    var(--line-color-border-2);        /* #e5e6eb */
--table-table-total:     var(--higreen-higreen-total);      /* #f1f6f7 */
--table-table-highlight: var(--higreen-higreen-highlight);  /* #a7e4e1 */
--table-table-area:      var(--higreen-higreen-area);       /* #f3f8f8 */
```

### 8.2 图表色序

主色共 12 色，**图例按 1—12 顺序使用，不跳跃选色**。业务固定语义优先于无含义的序列分配——有明确业务含义的序列（目标/实际/同比/环比）走 `--businesssemantic-bs-*`，不用 chart 系列。

`-30` 后缀是 30% 不透明度版本，用于面积填充、辅助线等。

### 8.3 AI 辅助分析背景

已有渐变资产，**不重新生成替代色**：

```css
--gradient-ai-analysis: linear-gradient(90deg,
  rgba(255,255,255,1) 0%, rgba(222,254,255,0.5) 41%,
  rgba(233,231,255,0.5) 69%, rgba(201,203,255,0.5) 100%);
```

## 9. 组件规格（实测）

本节数值全部来自 Figma 组件实测，已同步到 `digital-store-tokens.css` 第 16、17 段。
**尺寸、内距、状态色直接用变量，不要另估。** 承载组件仍用 Arco，只是把外观覆盖成下面这样。

### 9.1 指标卡 IndicatorCard【确认】

两种开发模式的结构一致（图标 / 标题 / 数值 / 辅指标 / 趋势），差别在**宽度、内距、状态档位**：

| 项 | 自开发（721:26268） | QBI（1997:5040） |
|---|---|---|
| 布局变体 | 左右 / 上下 | 左右 / 上下 |
| 状态变体 | 常规 / 趋势默认 / 趋势选中 | 常规 / 趋势默认 / 趋势选中 / 联动未选中 / 联动选中 |
| 宽度 | 左右 **232px**、上下 **237px** | 两种布局统一 **252px** |
| 高度 | 两种均 **108px** | 左右 **102px**、上下 **114px** |
| 内层内距 | `12px` | 左右 `24px 12px`、上下 `12px` |
| 内层 gap | `8px`（上下布局居中） | `8px`（上下布局居中） |
| 内层圆角 | `6px` | `6px` |
| 外层包装圆角 | `8px` | `8px` |
| 独有属性 | `提示` `标签` `环比同比` `标题后图标` `箭头` | 多一个 `主指标标题` |

**QBI 多出的两档联动态**：`联动未选中` = 整体 `opacity: 0.5`，`联动选中` = 换成选中底色。
自开发没有联动态，不要给它加半透明效果。

内容三行间距 `4px`（`--indicatorcard-content-gap`），别把标题、数值、辅指标铺成 8px 均分的三行。

趋势态底色不同：自开发 `--indicatorcard-bg-trend`（`#F7F8FA`）、QBI `--indicatorcard-bg-trend-qbi`（`#F5F5F5`）。
普通态两边都用 `--indicatorcard-bg`（`#F5F7FB`）。

内层 `6px` 圆角是历史实例，**不在 3.3 的 4/8 两档里，不要扩散到其他组件**。

### 9.2 按钮 Button【确认】

三套按钮是**两层关系**，不是三选一：

- **自开发按钮**（688:31394）与**QBI 按钮**（3567:17805）是**业务专用按钮**：文字写死（返回 / 重置 / 提交 / 导出 / 查询 / 毛利率日报 / 全渠道口径明细），尺寸与圆角跟通用按钮一致。
- **通用按钮**（5351:2403）是**底座**，五型四态都由它定义。业务专用按钮只是它的具体实例。

自开发与 QBI 的差别只有一处：**底色**。自开发是描边款（`#F7F8FA` 底 + `#C9CDD4` 边），QBI 是品牌实心款（`#00AAA6` 底 + 白字）。其余完全一致。

尺寸（两套共用）：

| 项 | 值 |
|---|---|
| 高度 | `32px` |
| 内距（有文字） | `5px 8px` |
| 内距（纯图标） | `9px` |
| 圆角 | `4px` |
| 文字与图标间距 | `8px`（纯图标 `10px`） |
| 图标尺寸 | `14×14` |
| 文字样式 | `14/CN-Regular` = PingFang SC 400 / 14px / 22px |
| 边框 | `1px` |

通用按钮五型四态配色（**照表取，不要自己调深浅**）：

| 类型 | 默认 | 悬停 | 激活 | 禁用 |
|---|---|---|---|---|

#### 上表有两处与无障碍底线冲突，按下面处理

1. **主要按钮 `#00AAA6` + 白字只有 2.88:1**，14px 文字不达 WCAG 4.5:1。

   优先改用 `#009093`（即 active 档）作 hover，`#00757B` 作 active——从默认到 hover 是变深的连贯序列。只在要求 100% 复刻设计稿时才照原值。

这两条不是否定规范，是规范值尚未走无障碍评审；交付时在说明里点一句即可。

### 9.5 筛选器栏 FilterBar【确认】

**它是容器，不是组件。** 内容由 tabs-capsule + select + datepicker 按业务组合，右侧挂按钮组。两种开发模式的容器规则不同：

| 项 | 自开发（4072:11058） | QBI（3567:17929） |
|---|---|---|
| 圆角 | `0 8px 0 0`（**只右上角**） | `8px`（整块） |
| 内距 | `8px 16px` | `8px 12px` |
| 控件间距 | `8px` | `12px` |
| 高度 | 单行 `48px`；双行 `88px` | 单行 `8 + 34 + 8` = `50px` |
| 底色 | `#FFFFFF` | `#FFFFFF` |
| 字段标签 | **无** | **有**：标签在控件左侧，右间距 `8px`，`#4E5969` 14/400 |
| 底部线 | 部分变体有 `1px #E5E6EB`，其余无 | 无 |
| 右侧按钮 | `重置` = `66×32` 描边款（次要按钮） | 品牌实心，宽 `44px` |

自开发的圆角只给右上角，是因为它贴在内容区左上角、左边和下边都接别的块。**不要给它补满 8px 圆角**，会露出接缝。

布局规则：

1. **位置**：container 内容区**置顶**，占满内容宽。规范没有定义吸顶滚动；确实要吸顶时用 `--z-sticky`，并把上方顶栏一起算进 z-index。
2. **顺序固定**：粒度分段（tabs-capsule）→ 时间范围（datepicker）→ 维度下拉（select × N）→ 操作按钮组。从左往右，粒度最粗、按钮最后。
3. **对齐**：容器 `space-between`——左控件组靠左、按钮组靠右。控件变多时**先压缩下拉宽度**，不要把按钮挤到第二行。
4. **高度**：左侧控件按 9.6 的「32 / 34 二选一」定高，上下各留 `8px` → 走 32 时单行 `48px`、走 34 时 `50px`；两行 `88px`（`8 + 32 + 8 + 32 + 8`，行间距 `8px`）。
5. **QBI 的字段偏移不要照抄**：画板里各 `form-box` 的 `padding-left: 24 / 50 / 64` 是手工对齐留下的，真实字段间距就是 `select-box` 的 `gap: 12px`。照抄会在别的内容宽度下全乱。

左侧 16 / 间距 8（自开发）与 8px 栅格节奏同源，12 / 12（QBI）与 12px 节奏同源——两套各自自洽，**但不要跨模式混用**。

### 9.9 图标 Icons【确认】

系统图标分两层：**尺寸包 `icon-wrapper`**（决定多大）与**图标库**（决定画什么）。两层解耦，换图标不改尺寸。

导出的 SVG 是**填充路径**（`fill-rule="evenodd"`），没有 `stroke-width`。视觉线宽是几何本身，所以：

- 缩放不会变粗，但会变细：24 grid 下最细处约 `2px`，14 下约 `1.75`，**10 下约 `1.2px`**。
- `10` / `12` 两档在 1x 屏上已经发虚，只用在密集表格、标签这种“能看到轮廓就行”的地方。
- 不要给它加 `stroke` 去“加粗”——会在偶数尺寸上出现双线。

#### 组件里的已实测档位

| 场景 | 尺寸 | 依据 |
|---|---|---|
| select 箭头 / datepicker 减号 / 下拉对勾 | `12` | 见 9.6 与 9.7【确认】 |
| 按钮内图标 / 页签星标 | `14` | 见 9.2 与 9.4【确认】 |
| 小标题图标内嵌 | `20` | 见下方【确认】 |

其余档位（16 / 18 / 22 / 24 / 32 / 48）在组件库里存在，但**没有在已拉取的组件里看到实际用法**，不要自己编场景映射。

#### 小标题图标（渐变徽标）

指标卡、图表面板的小标题左侧用的那枚 24px 方孔徽标。

| 项 | 值 |
|---|---|
| 外层尺寸 | `24×24` |
| 内嵌图标 | `20×20` 白色，四边各 `2px` |
| 圆角 | `6px`（历史实例，与 9.1 指标卡内层同值） |
| 底色 | `linear-gradient(143deg, #22BBB3 14%, #00AAA6 94%)` |
| 背景模糊 | `backdrop-filter: blur(10px)` |

业务口径变体共 10 个：外销 / 内销 / 收入销量 / 均价 / 毛利率 / 库存销量 / 销量 / 利润 / KPI / 金额。
口径名直接写在变体上，**不要把十个口径做成一个可配文字的通用容器**——它们是对应业务概念的既有资产。

#### 落地

```html
<svg class="icon" viewBox="0 0 24 24" aria-hidden="true">
  <use href="#icon-name" />
</svg>
```

```css
.icon { width: var(--icon-size-16); height: var(--icon-size-16); fill: currentColor; }
```

三条硬约束：

1. **用 inline SVG + `currentColor`**，不要一个颜色导一份文件。颜色由父级 `color` 决定，图标自己不持有色值。
2. **`viewBox` 统一固定为 `0 0 24 24`**（源文件就是 24 grid），尺寸只用 CSS 的 `width/height` 控制。每档写一个 viewBox 会让同一图标的路径重复十份。
3. **功能图标必须带文本或 `aria-label`**。纯装饰性图标加 `aria-hidden="true"`；不可只靠图标颜色表达状态。

**图标不是字体。** 不要用 iconfont 或 emoji 替代：iconfont 会因字体未加载变成方块，emoji 跨平台渲染不一致，颜色也不受 `currentColor` 控制。

## 10. 页面骨架

生成时从下面选骨架，不要从零设计布局。

### 10.1 列表 / 分析页（最高频）

```
┌─────────┬──────────────────────────────────────────┐
│ 侧栏    │ 顶栏 Tab (42px)                          │
│ 178px   ├──────────────────────────────────────────┤
│ 深色    │ FilterBar (48px) 粒度│日期│下拉×N│重置   │
│ 分组    ├──────────────────────────────────────────┤
│ 导航    │ 标题区 (48px)                            │
│         ├──────────────────────────────────────────┤
│         │ 指标卡区    （卡内距 8、卡间 8）          │
│         ├──────────────────────────────────────────┤
│         │ 图表 / 表格（一级容器，圆角 8）           │
│         ├──────────────────────────────────────────┤
│         │ AI 辅助分析（渐变背景）                   │
└─────────┴──────────────────────────────────────────┘
   └─ 主工作区 W = 页面宽 − 178 ─┘
```

要点：
- 侧栏深色，与内容区形成明确分区；内容区底色用 `--higreen-bg-page-01` 一类浅底，白卡浮在上面。
- 筛选行（FilterBar）所有控件同一水平线、同一高度，右对齐「重置」，可加「展开」。容器规则见 9.5：自开发 `0 8px 0 0` + `8px 16px`，QBI 整块 `8px` + `8px 12px`。
- 指标卡区内距 8px、卡间 8px，**跨列模块间也是 8px 净距**。
- 图表与表格切换用右上角「图表 | 表格」，不用两块并排。

### 10.2 详情 / 编辑页

- 左侧或顶部给返回路径，不留死胡同。
- 表单字段字号 ≥14px；移动端输入框 ≥16px 防 iOS 放大。
- 危险操作（删除、作废）二次确认或可撤销。

### 10.3 移动端（如有）

- 边距与槽沿用同一场景值，最小字号 10px，但输入框仍 ≥16px。
- 贴边栏用 `env(safe-area-inset-*)` 留安全区。
- 移动 Tabbar 的阴影用横向偏移，不套桌面阴影。

### 10.4 页面模板 / 多页面 demo【确认】

同一份规范里展示多张典型页面（目录 + 点击进详情）时，只做**框架布局 + 组件拼装**，三条硬规则：

1. **页面里的每个区块都取组件库组件，禁止自造简化版。** 典型页 = 指标卡 `.ind`（9.1）+ SideNav `.sn`（第 13 节）+ 页签 `.page-tabs`（9.4）+ FilterBar `.filterbar`（9.5，内含 DateSelected `.u-dsel`（9.6）、select、按钮 `.btn`）+ 趋势图 `.tc`（第 9 节组件集）+ AI 辅助分析 `.u-ai`（第 12 节）+ 表格 `.data-table` 与标签 `.tag`（13.1 / 11.4）。**不允许**用「灰色方块顶替指标卡 / 两条线顶替图表 / 纯文字块顶替 AI 区块」的示意版，那会让 demo 与组件规范变成两套外观。指标卡宽度按 Figma 实取：自开发 **232**、QBI **252**（组件默认）、页面联动卡 **197**（`.is-xs`，三列或单行 6 张）、等级卡 **300**（4 张 `is-fill` 在 1222 内宽里均分）、生命周期紧凑卡 **123×74**（`.is-compact`，仅标题 + 24 数值）；图表组件默认 **236**，页面内按设计稿取 208（份额图表面板）/ 251（趋势图卡）/ 260（组合图）/ 280（双折线）/ 300（备件趋势）/ 338（百分比堆积）/ 342（分品类折线），均直接复用组件实例已有尺寸。
2. **缩略图必须是同一份页面 DOM 的等比缩放，不是手绘骨架。** 缩略图容器 `.tpl-thumb-win` 内放一个 1440×900 的 `.tpl-thumb-doc`，内容由**与预览页完全相同的拼装函数**生成，`transform: scale(容器宽/1440)` + `transform-origin:0 0` 等比缩放；缩略图内 `pointer-events:none`，hover 才出深色遮罩与「› 预览」。不允许用色块拼一张近似图——要求「缩略图与页面实际一致」时，唯一可交付的做法就是同一份 DOM。
3. **交互：点缩略图 → 目录被整页替换**，页面全宽挂载在同一节内（不是弹窗、不是 iframe、不是缩放画布），左下角悬浮「返回」按钮回目录，`Esc` 也可返回。预览页里图表用 ECharts 真渲染，缩略图内换 SVG 折线/柱形，避免 canvas 缩小后发虚。**图表容器的 `id` 只在预览页输出**（`forThumb` 为 true 时不写 id），因此缩略图与预览页同时存在于 DOM 时不会产生重复 id；ECharts 初始化一律 `pageEl.querySelector('#'+id)` 定位，不用 `document.getElementById`，否则会命中隐藏缩略图里的同名节点。

落地检查：预览页与缩略图共用同一个 `pageHtml(def, id, forThumb)`，`forThumb` 只切换图表实现（ECharts ↔ SVG），其余 DOM、类名、层级逐字相同；页面框架只保留布局类（`.tpl-page` / `.tpl-main` / `.tpl-title` / `.tpl-body` / `.tpl-row` / `.tpl-block`），不自造任何内容组件。新增页面时只允许用**布局位**摆位：`.tpl-panel`（白卡内距 8）、`.tpl-subpanel`（#FBFBFB 二级块）、`.tpl-grid-3`（三列 gap 10）、`.tpl-cards-3` / `.tpl-cards-4`（197 卡栅格）、`.tpl-figure*`（份额右侧图表面板）、`.tpl-col-strip`（列即字段的卡列表）、`.tpl-scroll-x` + `.data-table.is-frozen`（长表首列冻结）、`.tpl-ai-ball`（右下 AI 悬浮球）。筛选器三型：自开发 48 高（`.filterbar`）/ 份额页胶囊 + 展开·重置·奥维行业概览 / QBI 50 高（`.filterbar-qbi`，字段 > 4 自动两行 88 高，`.is-wrap`）。

## 11. 图表与数据展示

### 11.1 趋势表达

- 涨跌用**红/蓝**，不用绿。
- 涨跌同时给箭头（▲▼）和数字，**不能只靠颜色**。
- 百分比保留一位小数（如 23.3%），不要凑整成 25%。

### 11.2 指标卡内容顺序

```
指标名（14/400，--text-color-text-2）
数值 + 单位（36/36 D-DIN-PRO，--text-color-text-1；单位降一档、用 text-3）
辅指标：环比 / 同比 / 完成率（12/16，--text-color-text-3）+ 箭头 + 涨跌色
```

尺寸与内距见 9.1，两种开发模式不同，不要混用。三行之间用 `4px`，不是 8px。

### 11.3 双轴图

- 左轴为数值，右轴为百分比，各自标注单位。
- 坐标轴用 `--chart-axis`，网格线用 `--chart-grid`。
- 主序列用实线 + 30% 面积填充，对比序列用虚线，图例放在图表上方居中。
- 不超过 3 条序列同图；多了换小倍数（small multiples）或分图。

### 11.4 表格

- 数字列右对齐并开 `tabular-nums`；文本列左对齐。
- 表头用 `--table-table-head`，不加粗边框。
- 合计行用 `--table-table-total`，并固定在表尾。
- 长内容（长门店名、长品类名）要能截断 + hover 显示全称，不能撑破列宽。

## 12. AI 辅助分析模块

这是本平台最特殊的模块，通用审计清单管不到，单独说明。

- 容器背景用 `--gradient-ai-analysis`，不重新生成替代渐变。
- 结构：标题行（含「AI辅助分析」+ 右侧「一键展开」）→ 分类条目列表。
- 每条：左侧品类标签（`13px` 左右，用 `--primary-primary-8`）→ 右侧分析文本。
- 文本中的数字和趋势词要做**行内高亮**（涨用红、跌用蓝，与 3.1 一致），这是该模块的核心可读性手段。
- 条目可折叠，展开态给出更细的分项；不要一次把所有内容铺开。

## 13. 交付自检

生成后逐项对照，**这 16 条是本规范最容易翻车的地方**：

1. 涨跌是「红好蓝差」吗？有没有误用绿色表示上涨？
2. 品牌绿有没有被用来写正文或小图标？（只能用 `primary-7` / `primary-8`）
3. 圆角是否只有 4 和 8？有没有混进 Arco 的 16px？（**例外只有两个：指标卡内层 6px、小标题图标 6px**，其余一律 4 / 8）
4. 字体是否走了 fallback 栈？D-DIN-PRO 字体文件是否存在？
5. 数字是否开了 `tabular-nums`，单位是否退了一档？
6. `text-3` 有没有被用在 14px 正文上？
7. 栅格节奏判断对了吗？（数字化门店 8px / 其余 12px）
8. 指标卡与卡间净距是否一致，跨列模块是否 8px 净距？
9. 图表图例是否按 chart-1 到 chart-12 顺序取色，没有跳跃？
10. `--status-*` 有没有被按字面语义使用？
11. 开发模式判对了吗？（QBI = 252 宽指标卡 + 品牌实心按钮；自开发 = 232/237 + 描边按钮）
12. Tabs 层级有没有跨级？（L1 下划线 / L2 灰底胶囊 / L3 纯文本竖线 / 切换 绿底胶囊）
13. 页签和 Tab 有没有混用？（页签是浏览器标签语义，`4px 4px 0 0` 上圆角 + `#FAFAFA` 底）
14. 筛选器栏判对了吗？（自开发 `0 8px 0 0` + `8px 16px` + 间距 8、字段无标签；QBI 整块 `8px` + `8px 12px` + 间距 12、字段带标签）
15. 同一筛选行的控件底边对齐了吗？（select 与自开发胶囊 32、datepicker 与 QBI 胶囊 34，二选一，不要混排）
16. 图标是否走 `currentColor`？有没有一份颜色一个 SVG 文件、或拿 iconfont / emoji 顶替？

外加 `references/web-baseline.md` 的全部底线项（点击区域、移动端输入、状态不只靠颜色、长内容、危险操作可挽回、每个界面有下一步）。
